# 简历表述

下面每一个数字都能在仓库的结果文件里查到，括号内注明出处。

## 完整版（评测 / 数据岗）

**具身策略鲁棒性评测｜LeRobot、Diffusion Policy、PushT、Python**　[github.com/yinqi2151-tech/pusht-policy-eval](https://github.com/yinqi2151-tech/pusht-policy-eval)

- **评测流程校验**：早期评测第三方权重时，成功率只有 0–5%。核对训练配置后发现，所用的 Diffusion 权重只训练了 1000 步（官方为 20 万步）。之后修复了 LeRobot 0.6.1 迁移旧格式权重时的配置序列化 bug，改用官方权重复测，50 回合的平均最高奖励为 0.952（官方 0.955），证明评测流程本身可信。（`docs/validation.md`）
- **可复现与提速**：定位到原生评测在同一种子下结果不可复现的原因（0.614 和 0.392，来自 cuDNN benchmark），改用确定性设置后修复。在保证逐步轨迹逐位一致的前提下，用批量并行把评测提速 11.5 倍（每回合 50 s → 4.4 s）。（`results/checks/determinism_batch25.json`）
- **配对鲁棒性实验**：不修改 LeRobot 源码，在每个仿真子环境外包上扰动层和逐步状态记录层，设计 21 个条件、每个条件 100 个配对初始状态的实验，用精确 McNemar 检验加 Holm 校正做统计，并以重新采样作为对照，量化策略自身的随机波动（同一初始状态的成败在重复运行中翻转 33–46 次）。主要结论：动作噪声 σ=20 px 时成功率从 57% 降到 15%；执行延迟 400 ms 时降到 33%，200 ms 以内影响不显著。（`results/sweep_summary.md`）
- **用对照实验纠正结论**：16 px 的灰色遮挡让成功率从 57% 降到 2%。通过轨迹分析和设计对照实验，发现原因是策略把与 T 颜色相近的色块当成了推动目标（88% 的回合里推杆主动靠近方块）。同样位置的白色方块下成功率为 59%，与无扰动无差异，说明问题不在于信息被遮挡。（`results/sweep_summary.md`、`docs/protocol.md`）
- **失败归因与人工验证**：基于逐步轨迹把每个回合自动归入 5 类结局，阈值在实验前固定；再抽取 40 个回合做分层盲审。在第一轮复核中发现回放视频的渲染 bug，修复后补上回归测试，并重新抽样复核。最终 3 类结局的人机一致率为 90%（κ=0.82）；5 类细分只有 52.5%，据此限定了结论能引用的分类层级。（`docs/failure_taxonomy.md`）

## 精简版（产品 / 运营岗）

- 为开源机器人策略搭建可复现的评测流程：先用官方基准校验评测本身，再定位出早期得分低的原因是所选模型训练不足。
- 设计配对的鲁棒性实验，并用对照组区分真实影响与随机波动；发现策略对颜色相近的干扰物极其敏感，这一结论推翻了"遮挡导致失败"的初步判断。
- 用人工盲审检验自动失败分类，发现并修复了回放渲染的 bug，最终只在验证可靠的分类层级上下结论。

## 面试时说明

- 只评测了一个策略、一个仿真任务，扰动是人为合成的，结论不外推到真实机器人。
- 校验用的 50 回合成功率 54%，低于官方的 65.4%，但在统计误差范围内，不宣称精确复现。
- "轻度图像噪声反而提高成功率"在校正后不显著，也接近重复运行的波动范围，没有作为结论。
- 白色方块和重新采样两组对照，是看到主扫描结果之后才加的，报告中已明确标注。
- 3 类合并是看到复核结果之后才决定的，属于事后分析；修订后的 5 类规则需要用新样本重新验证。
- 代码在 AI 编程工具协助下完成；实验设计、问题定位、运行和结论核对由本人负责。
