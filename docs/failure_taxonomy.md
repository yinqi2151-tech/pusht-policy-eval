# 回合结局分类

规则写在 `src/pusht_eval/failures.py` 里，阈值在运行任何扫描回合之前就已固定。五类互斥，按下面的顺序判定，命中第一条即停止：

| 类别 | 判定规则 | 在回放视频里的样子 |
| --- | --- | --- |
| `success` 成功 | 覆盖率曾超过 0.95（环境自带判定） | T 形物块与绿色目标基本重合，回合提前结束 |
| `no_push` 未推动物块 | 物块中心的总移动路程 < 5 px，且累计转角 < 3° | 推杆始终没有真正推动物块 |
| `near_miss` 接近但未达阈值 | 最高覆盖率 ≥ 0.85，但从未超过 0.95 | 物块已大体到位，在目标附近反复微调直到超时 |
| `lost_progress` 接近后推离 | 最高覆盖率 ≥ 0.40，但最终覆盖率低于最高值的一半 | 曾经推到目标附近，之后又把物块推走 |
| `insufficient` 推动但进展不足 | 以上都不满足 | 推动了物块，但始终没有接近目标 |

这些类别描述的是记录下来的状态变化，不是失败的原因。例如 `near_miss` 只说明“差一点”，没有说明是朝向没对齐还是位置偏了。

## 人工复核

`scripts/make_review_sample.py` 按类别分层抽样：每类最多 8 个回合，尽量分散到不同条件，并按记录的状态重新渲染回放视频。复核采用盲审：

- 视频只按匿名编号命名（R01、R02……），画面上只显示步数，不显示类别或覆盖率。
- 条件、种子和自动分类结果另存在 `review_key.csv` 里，标注完成之前不要打开。

复核人观看视频后，在 `review_sheet.csv` 的 `human_category` 一栏填写上表五个类别之一（用英文名），有需要可以在 `notes` 里补充说明。然后运行 `scripts/review_agreement.py`，它会输出准确率、Cohen's κ 和混淆矩阵（行是自动分类，列是人工标注）。

报告里只引用一致率，不用人工标注替换自动分类。如果某一类的一致率明显偏低，应当修改规则，然后在全部数据上重新分类；同时要在报告中写明规则改过，并说明原因。

## 回放视频的标记

- 红色十字：环境实际执行的目标位置。
- 蓝色圆圈：策略原本输出的目标位置。只在加了动作噪声或延迟、两者不一致时才显示。
- 灰色方框：遮挡和擦除条件下，方块在画面中的位置。

## 复核结果

**第一轮（作废）**：回放视频里 T 的位置画错了（见 `results/review_v1_misrendered/README.md`），一致率 57.5%（κ=0.47）不能用来评价分类规则。

**第二轮**：重新抽样，排除第一轮出现过的回合，从 21 个条件中每类抽 8 个，共 40 个回合，使用修复后的回放视频。

| 自动分类 ＼ 人工标注 | success | no_push | near_miss | lost_progress | insufficient |
| --- | ---: | ---: | ---: | ---: | ---: |
| success | 6 | 0 | 1 | 1 | 0 |
| no_push | 0 | 8 | 0 | 0 | 0 |
| near_miss | 2 | 0 | 2 | 4 | 0 |
| lost_progress | 0 | 0 | 0 | 1 | 7 |
| insufficient | 0 | 0 | 3 | 1 | 4 |

- 5 类一致率为 52.5%（21/40），Cohen's κ=0.41。
- 事后把三个"部分进展"子类合并为一类后，3 类一致率为 90%（36/40），κ=0.82。
- 不一致的主要来源：
  1. `lost_progress` 把峰值覆盖率 0.40 当作"接近过目标"，而复核人认为这算不上接近，因此判为"进展不足"（8 个中有 7 个）。
  2. 覆盖率曾达到 0.85 以上、之后又被推开的回合，规则判为 `near_miss`，复核人倾向于判为 `lost_progress`。
  3. 覆盖率在 0.95 附近时，"成功"和"差一点"在画面上难以分辨（2+2 个）。

**结论**：只在"成功 / 未推动 / 部分进展"这一级引用自动分类，三个部分进展子类仅作描述。可以考虑的规则修订包括：把 `lost_progress` 的峰值门槛提高到 0.85，并让它的判定优先于 `near_miss`。但这些修订是根据本轮样本提出的，必须在新的一轮抽样上验证之后才能采用，目前尚未实施。
